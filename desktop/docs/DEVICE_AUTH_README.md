# Device Flow Authentication for Scizor Desktop

This document describes the implementation of device flow authentication for the Scizor desktop application using PKCE (Proof Key for Code Exchange).

## Overview

The device flow authentication allows desktop applications to securely authenticate users without exposing sensitive credentials. It follows the OAuth 2.0 device authorization grant flow with PKCE for enhanced security.

## Architecture

### Components

1. **Desktop App (Client)**
   - `DeviceAuthManager`: Manages the authentication flow
   - `AuthPanel`: UI component for authentication
   - Local HTTP server for receiving callbacks

2. **Website (Authorization Server)**
   - `/auth/device`: Device authentication page
   - `/auth/device/consent`: Consent page for granting permissions

3. **Backend (Token Server)**
   - `/auth/device/token`: Token exchange endpoint
   - `/auth/device/refresh`: Token refresh endpoint

## Implementation Details

### Desktop App

#### DeviceAuthManager

The `DeviceAuthManager` class handles the complete authentication flow:

```python
# Initialize the auth manager
auth_manager = DeviceAuthManager()

# Start the authentication flow
success = auth_manager.start_auth_flow()

# Check authentication status
if auth_manager.is_authenticated():
    # User is authenticated
    headers = auth_manager.get_authenticated_request_headers()
```

**Key Features:**
- PKCE code verifier and challenge generation
- Local HTTP server for receiving authorization codes
- Secure token storage
- Automatic token refresh
- Logout functionality

#### AuthPanel

The `AuthPanel` provides a user-friendly interface for authentication:

```python
# Create the auth panel
auth_panel = AuthPanel()

# Connect to signals
auth_panel.auth_success.connect(on_auth_success)
auth_panel.auth_failed.connect(on_auth_failed)
```

### Website

#### Device Authentication Page (`/auth/device`)

Handles the initial authentication step:
- Extracts PKCE parameters from URL
- Provides login/signup forms
- Redirects to consent page after authentication

#### Consent Page (`/auth/device/consent`)

Shows permission request to user:
- Displays app information and requested permissions
- Allows user to grant or deny access
- Generates authorization code and redirects to desktop app

### Backend

#### Token Exchange Endpoint (`/auth/device/token`)

Exchanges authorization code for tokens:

```typescript
POST /auth/device/token
{
  "authorization_code": "auth_1234567890_abc123",
  "code_verifier": "code_verifier_string",
  "redirect_uri": "http://localhost:8080/callback"
}
```

Response:
```json
{
  "success": true,
  "message": "Token exchange successful",
  "data": {
    "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "refresh_token": "refresh_token_string",
    "user_id": "user123",
    "expires_in": 3600,
    "token_type": "Bearer"
  }
}
```

#### Token Refresh Endpoint (`/auth/device/refresh`)

Refreshes expired access tokens:

```typescript
POST /auth/device/refresh
{
  "refresh_token": "refresh_token_string"
}
```

## Security Features

### PKCE (Proof Key for Code Exchange)

- **Code Verifier**: Random string generated by desktop app
- **Code Challenge**: SHA256 hash of code verifier
- **Purpose**: Prevents authorization code interception attacks

### Token Security

- **Access Tokens**: Short-lived (1 hour) JWT tokens
- **Refresh Tokens**: Long-lived (7 days) for token renewal
- **Secure Storage**: Tokens stored in user's home directory
- **Automatic Refresh**: Handles token expiration transparently

### Local Server Security

- **Port 8080**: Fixed port for callback handling
- **Localhost Only**: Server only accepts local connections
- **HTTPS Not Required**: Local connections are secure

## Usage Examples

### Basic Authentication

```python
from auth.device_auth import DeviceAuthManager

# Initialize auth manager
auth_manager = DeviceAuthManager()

# Check if already authenticated
if not auth_manager.is_authenticated():
    # Start authentication flow
    auth_manager.start_auth_flow()
else:
    print("Already authenticated!")
```

### Making Authenticated Requests

```python
# Get headers for authenticated requests
headers = auth_manager.get_authenticated_request_headers()

# Use headers in API requests
import requests
response = requests.get(
    "http://localhost:3001/api/user/data",
    headers=headers
)
```

### Handling Authentication Events

```python
from PyQt6.QtCore import QObject, pyqtSlot

class AuthHandler(QObject):
    @pyqtSlot(dict)
    def on_auth_success(self, token_data):
        print(f"Authenticated as user: {token_data['user_id']}")
    
    @pyqtSlot(str)
    def on_auth_failed(self, error):
        print(f"Authentication failed: {error}")

# Connect signals
auth_manager.auth_completed.connect(self.on_auth_success)
auth_manager.auth_error.connect(self.on_auth_failed)
```

## Troubleshooting

### Common Issues

1. **Port 8080 Already in Use**
   - Change the port in `DeviceAuthManager._start_local_server()`
   - Update the redirect URI accordingly

2. **Authentication Fails**
   - Check that website and backend are running
   - Verify URLs in configuration
   - Check browser console for errors

3. **Token Refresh Fails**
   - Verify JWT_SECRET is set in backend
   - Check token expiration times
   - Ensure refresh token is valid
